# お問い合わせフォームの送信の仕組み（設置の手順）

**【未検証】まだ設置していない。**設置して一通送ってみるまでは、サイトのフォームは「メールアプリを開く」動きのまま。

設置は Dots が進めている（2026-11-26。Apps Script のプロジェクト「tsam お問い合わせ」を作成済み、未公開）。
機械よけは Cloudflare Turnstile（本物のボット判定）。受け口のソースはこのリポジトリの `forms/contact.gs` が正で、Dots はこれを貼って設置する。

## しくみ

新しいサイトは置いてあるだけのファイルなので、自分ではメールを送れない。そこで Google Apps Script（Google アカウントがあれば無料で使える小さな受け口）を一つ作り、
フォームはそこへ送る。受け口が ikemori@tsam.co.jp へメールを出す。

```
フォーム（tsam.co.jp） → Google Apps Script（forms/contact.gs） → ikemori@tsam.co.jp
```

- 届くメールの返信先は書いた人のアドレスなので、そのまま返信できる
- 送り主（From）は、受け口を作った Google アカウントのアドレスになる
- 1日に送れる数に上限がある（無料の Google アカウントで 100 通ほど）。お問い合わせの数なら足りる
- さくらのメールの設定には何も触れない

- フォームに触った人のブラウザは、機械でないことの確認のために Cloudflare と通信する（読むだけの人は通信しない）

## 手順（池森さんの Google アカウントと Cloudflare のアカウントで。Dots が進める）

1. **Cloudflare で Turnstile のウィジェットを作る。**ホスト名は `tsam.co.jp`（見本で試すなら `tsam-co-jp.web.app` も）。
   出てくる**サイトキー**（公開してよい）と**シークレットキー**（公開しない）を控える
2. https://script.google.com/ のプロジェクト「tsam お問い合わせ」に、このリポジトリの `forms/contact.gs` の中身を貼る。保存
   - 歯車（プロジェクトの設定）で「appsscript.json マニフェスト ファイルをエディタで表示する」に印を付け、
     出てきた `appsscript.json` の中身を、このリポジトリの `forms/appsscript.json` に置き換える。
     これで、この受け口が求める権限は**「メールを送る」と「外のサービス（Cloudflare）に問い合わせる」の二つだけ**になる
   - 同じ設定の画面の「スクリプト プロパティ」に `TURNSTILE_SECRET` ＝ シークレットキー を入れる。
     **シークレットキーは、コードにもリポジトリにもチャットにも書かない。**入っていないあいだ、受け口は何も送らない。
     見本で試すあいだだけ、`HOSTS` ＝ `tsam.co.jp,tsam-co-jp.web.app` も入れる（本番に出したら消す）
3. 右上の「デプロイ」→「新しいデプロイ」→ 種類は「ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」を押す。初回は権限の許可を求められるので、許可する
5. 出てきた「ウェブアプリの URL」（`https://script.google.com/macros/s/…/exec`）を控える
6. その URL を `www/src/data/site.ts` の `contactEndpoint` に、サイトキーを `turnstileSiteKey` に入れて、サイトを出し直す
   （**二つとも入っているときだけ**、フォームはその場で送信する。片方でも空なら、メールアプリを開く動きのまま）
7. サイトのフォームから一通送って、ikemori@tsam.co.jp に届くこと、返信が書いた人に届くことを確かめる
8. プライバシーポリシーに、フォームの機械よけに Cloudflare の仕組みを使うことを一行足す

## 知っておくこと

- 受け口の URL とサイトキーは秘密ではない（サイトの中に見える）。受け口は「決まった宛先にメールを出す」ことしかしないので、知られても宛先は変えられない
- 機械に Google の送信枠を使い切られないための関門は四つ（2026-11-26、Dots の指摘で足した。`contact.gs` の頭に詳しく書いてある）
  1. **Cloudflare Turnstile の確認**。フォームは、ブラウザが Cloudflare からもらった確認を添えて送り、受け口がそれを Cloudflare に問い合わせて確かめる。
     確認が無い・通らない・使い回し・別のサイトや別の用途のもの、は送らない。フォームを通らずに送信だけ投げる機械はここで止まる
  2. 人に見えない欄（埋まっていたら捨てる）
  3. **1時間に10通、1日に40通まで**。数は消えない場所に持ち、数えるあいだは鍵をかける
  4. Google の送信枠の残りが20通を切ったら送らない
- フォームが送る欄：name・organization・email・topic・message・website（人には見えない欄）・cf-turnstile-response（用途の名前は `tsam_contact`）。
  返ってくるのは `{ok:true}` か `{ok:false, error: invalid | verification | busy | server}`（失敗でも HTTP は 200）
- 控え（スプレッドシート）は残さない作りにした。メールが届かなかったときの控えが要るなら、権限を足す話になるので相談
- 筋道の確認は `node forms/contact.test.cjs`（Google と Cloudflare の部品を真似た箱の中で17件）。**本物で確かめたことにはならない**。
  サイト側は、Cloudflare が配っている試験用のサイトキーと手元の模擬の受け口で、通る場合・確認の欄が出る場合・やり直しを確かめてある
- コードを直したら、Apps Script の画面で貼り直して「新しいバージョン」でデプロイし直す。URL は変わらない
- やめるときは、Apps Script の「デプロイを管理」でアーカイブし、`contactEndpoint` を空に戻す（メールアプリを開く動きに戻る）
- 2026-11-26 の朝に一度、Cloudflare を使わない版（受け口が自分で札を出す）を作ったが、Dots の方針で Turnstile に替えた。
  札の版は「頁を開いて数秒待つ機械」を止められないため。git の履歴（cdd89a1）に残っている

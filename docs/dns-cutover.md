# 切り替えの手順書（確認用の最終版・2026-11-26）

tsam.co.jp と blog.tsam.co.jp を、さくらVPS の旧サイトから、新しい静的サイト（Firebase Hosting）へ切り替える手順。
**メールの行き先（MX）とサイトの行き先（A・CNAME）は、まだ変えていない。オーナー（ユウキさん）がこの手順を見て了承してから動かす。**

DNS（お名前.com）と Firebase を触るのは Dots。サイトの中身とこの手順書は Claude。さくらのサーバーには誰も入らない前提で書いてある。
オーナーの一番の心配は「さくらのメールに色んなアドレスを紐づけている。壊れたら参る」（2026-11-25）。
だから順番は **メールを先に安全な場所へ逃がす → 確かめる → それからサイト** で、逆にしない。

`tsam.jp` は別のドメインで、同じさくらVPS（160.16.226.77）を指している。Gmail の送信はこの名前で繋いでいる。こちらには触れない。

### 分かっていること

- **MX が tsam.co.jp そのものを指している。**サイトの A を先に変えると、メールも一緒に Firebase へ行って届かなくなる。だから B が先
- **メールの流れ**：tsam.co.jp 宛て → さくらVPS で受ける → Gmail へ転送。受信は MX さえ正しければ、サイトの切り替えの影響を受けない
- **Gmail の送信**（2026-11-26、Dots が画面で確認）：一つ目の Gmail は SMTP が `tsam.jp`・465番・SSL。`tsam.co.jp` ではないので、
  サイトの A を変えても送信は止まらない。もう一つの Gmail は未確認（上のお願い 3）
- **SPF** は、さくらVPS の IP を直に書いたもの。メールはこれからも同じ IP から出るので変えない。新しいサイト（Firebase）はメールを送らない。
  お問い合わせフォームの通知は Google のアカウントから Gmail のアドレスで出るので、tsam.co.jp の SPF には関わらない
- **blog・101・investors・test・wp は本体への相乗り**（CNAME）。本体の A を変えると一緒に動く。
  いまのブログは記事を `tsam.co.jp/wp-json/…` から読んでいるので、ブログだけさくらに残すことはできない。**公式とブログは同時に切り替える**
- **消すと決まったもの**：101（オーナー 2026-11-25）、investors・test・wp（オーナー 2026-11-26）
- **証明書**（Dots が 2026-11-26 に実際に繋いで確認）：`tsam.jp` と `tsam.co.jp` の 443番・465番とも正常で、2027-01-29 10:43（日本時間）まで有効。
  公開の発行記録（crt.sh）では、さくらVPS の証明書は二枚に分かれている。`tsam.jp` だけのものと、`tsam.co.jp`・blog・101・investors・test・wp の六つをまとめたもの。
  どちらも Let's Encrypt で、ふだんは60日ごとに自動で更新されている
  - 六つまとめたほうは、切り替えのあとは更新が通らなくなる（名前が Firebase へ移るか、消えるため）。もう使わない証明書なので、それでよい
  - **メールの送信が頼っているのは `tsam.jp` のほう**（のはず）。これが切り替えのあとも自動で更新され続けることを、関門 3 で確かめる
    （2026-11-26 に Claude が「期限が 11-30 で更新が出ていない」と書いたのは誤り。発行記録に新しい証明書が載っていなかっただけだった）

## A. 準備【済み】

- `mail.tsam.co.jp`　A　`160.16.226.77` を追加（2026-11-26、Dots）
- Firebase（プロジェクト `my-retro-bbs`）にサイト `tsam-co-jp`（公式）と `tsam-blog`（ブログ）を作成。独自ドメインを仮に登録。
  持ち主確認の TXT `hosting-site=tsam-co-jp` を追加（同）
- 3日限定の見本で、中身と URL の動きを確認（教科書40頁が 200、末尾スラッシュ40本が一回の 301、ブログ165本の番号が一致）

## B. メールの宛先を付け替える（見た目は何も変わらない）

| 名前 | 種類 | いま | 変えたあと |
|---|---|---|---|
| tsam.co.jp | MX | `10 tsam.co.jp.` | `10 mail.tsam.co.jp.` |

`mail.tsam.co.jp` はいまと同じさくらVPS を指しているので、メールの届く先は変わらない。変わるのは「名前の引き方」だけ。
受信のとき、送り手のサーバーは証明書の名前まで確かめないのがふつうなので、さくら側の証明書に `mail.tsam.co.jp` が入っていなくても届く
（それでも下のテストで実際に確かめる）。

**確かめること（これが通るまで D に進まない）**
1. 変えた直後と、2時間後（古い値が世の中から消えたあと）の二回、
   - 外のアドレス（Gmail と、Gmail 以外を一つずつ）から、よく使う tsam.co.jp のアドレス数本へ送り、いつもの Gmail に届くこと
   - tsam.co.jp のアドレスを差出人にして Gmail から送り、相手に届くこと（迷惑メールに入らないこと）
2. `dns.google` などで MX が `10 mail.tsam.co.jp.` と引けること

**戻し方**：MX を `10 tsam.co.jp.` に戻す。

## C. 新しいサイトの中身を Firebase に出す（tsam.co.jp はまだ旧サイトのまま）

- Dots が、見本で確かめたのと同じ版（コミットの番号で固定）を、`tsam-co-jp` と `tsam-blog` の二つだけに出す
  （`firebase deploy --only hosting:tsam-co-jp,hosting:tsam-blog --project my-retro-bbs`。同じプロジェクトにある off-notes のサイトには触れない）
- 出ると `https://tsam-co-jp.web.app/` と `https://tsam-blog.web.app/` で誰でも開けるようになる。
  各頁は「正しい住所は tsam.co.jp」（canonical）と名乗っているので、検索に二重に載る心配は小さい
- Claude が、その二つの URL で全頁の検査（`URL=https://tsam-co-jp.web.app node www/tools/verify.cjs` と、ブログの同じもの）と、URL の動きをもう一度確かめる
- お問い合わせフォームは、受け口（Google Apps Script）の設置がまだなので、**送信ボタンでメールアプリが開く動きのまま出す。**
  受け口ができたら、あとから差し替える（切り替えの関門にはしない）

**戻し方**：要らない。ドメインを向けるまでは、誰の目にも旧サイトが出ている。

## D. サイトの行き先を Firebase へ向ける

### 関門（全部そろってから）

1. B のメールの確認が、二回とも通っている
2. もう一つの Gmail の SMTP サーバーが `tsam.jp` である（`tsam.co.jp` だったら、先に `tsam.jp` へ書き換えて送信を試す）
3. **さくらの `tsam.jp` の証明書が、切り替えのあとも自動で更新され続けると見込める**（オーナーの希望は、証明書を手で管理しなくて済むこと）。見るのは二つ。
   - `tsam.jp:465` が出している証明書の名前が `tsam.jp` だけであること。六つまとめたほうを出していたら、切り替えのあと更新が止まり、
     2027-01-29 に Gmail からの送信が止まる。その場合は、サーバーに入れる人に `tsam.jp` の証明書へ付け替えてもらうまで D をやらない
   - 更新の確かめ先が `tsam.jp` 自身であること（旧サイトの名前に頼っていないこと）と、更新された証明書がメールのサーバーにも反映されること。
     外からは見切れないので、**D のあと最初の更新（2026-12-30 ごろ）に、`tsam.jp:465` の証明書の期限が延びたかを見る**（E-5）。
     期限は 2027-01-29 なので、延びていなくても1か月の余裕がある
4. Firebase の側で、`tsam.co.jp` と `blog.tsam.co.jp` の証明書を先に用意できている（Firebase の「詳細設定」。用意できない場合は、
   切り替えの直後に証明書が出るまでのあいだ警告が出ることをオーナーに伝えたうえで進める）
5. C の確認が通っている
6. 四つのサブドメインを消すことを、オーナーが Dots に直接伝えている
7. （勧め）前の日に、`tsam.co.jp` の A と `blog.tsam.co.jp` の CNAME の TTL を短くしておく（お名前.com で選べるいちばん短い値）。戻すときに早く効く

「変えたあと」の二つの値は、Firebase の画面が 2026-11-26 に示したもの（Dots の報告）。**当日、Firebase の画面にもう一度出して、その値を使う。**

MX・`mail.tsam.co.jp`・TXT（SPF・Search Console・OpenAI・Firebase）は**触らない。**

切り替えてから1時間ほどは、人によって旧サイトが出たり新サイトが出たりする（どちらも動いているので、困る人は出ない）。

4. `http://` で開いても `https://` に送られる
5. **B と同じメールの送受信テストを、もう一度**
6. アナリティクス（リアルタイム）に、新しいサイトの表示が出る

### 戻し方

`tsam.co.jp` の A を `160.16.226.77` に、`blog.tsam.co.jp` を `tsam.co.jp.` の CNAME に戻す。消した四つは、上の表の「いま」の値で足し直す。
さくらのサーバーは止めていないので、戻せば旧サイトがそのまま出る（旧サイトの証明書は 2027-01-29 まで有効）。
MX と `mail.tsam.co.jp` はそのままでよい（どちらを向いていてもさくらに届く）。
